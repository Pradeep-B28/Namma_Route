1. What a graph is

A graph is a network of points called vertices, connected by lines called edges.

In Namma Route, each station is a vertex and the tracks between them are edges.

Each edge has a travel time in minutes.

Changing lines at an interchange takes extra time.

We model line transfers as edges with a five-minute penalty.

This lets the computer treat Chennai transit as a mathematical network.

2. Dijkstra

Dijkstra was invented by Edsger Dijkstra in 1956.

It finds the fastest path by exploring outward in every direction from the start.

It always checks the nearest reachable station first using a priority queue.

Once it visits a station, it knows the true shortest time to reach it.

Because it has no sense of direction, it explores stations behind you as well as ahead.

It is guaranteed to find the true fastest route on any network with positive times.

3. A* and its estimate

A* improves on Dijkstra by adding a sense of direction.

At every step, it considers the time spent so far plus an estimate to the destination.

In Namma Route, this estimate is straight-line distance multiplied by a safe speed constant.

The estimate must never overestimate the true remaining time.

Because the estimate is optimistic, A* is guaranteed to find the true fastest route.

It focuses search toward the goal and checks far fewer stations than Dijkstra.

4. BFS (Fewest Stops)

BFS explores a network level by level, like ripples spreading across water.

It checks all stations one stop away, then all stations two stops away.

BFS ignores travel time and line transfers completely.

It only minimizes the total count of station stops.

Sometimes a route with fewer stops takes longer because trains run slower or transfers take time.

BFS runs directly on the station graph where all lines at a station are merged.

5. Min-heap

Both Dijkstra and A* need to repeatedly pick the station with the smallest cost.

A simple list would take O(N) time to search through on every step.

A min-heap is a binary tree stored in a compact array.

The smallest item is always at the top at index 0.

Adding an item or removing the minimum takes only O(log N) operations.

This keeps the search fast and responsive even across large networks.

6. Big-O Complexity

Dijkstra with a min-heap runs in O((V + E) log V) time, where V is nodes and E is edges.

A* has the same worst-case bound, but visits far fewer nodes in practice.

BFS runs in O(V + E) time using a simple first-in first-out queue.

Without a heap, Dijkstra would take O(V squared) time, which is much slower.

Heap push and pop operations take logarithmic time proportional to tree depth.
